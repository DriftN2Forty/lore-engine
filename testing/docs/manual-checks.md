See [dated evidence](live-model-evidence.md). WSL-to-Windows loopback remains unreachable; the Windows-hosted app reaches the model. Live thirty-turn continuity and real-story voice review remain open.

Thirty-six requests were run across observational default, fresh disabled and fresh default rounds; see [results and limits](cache-comparison-evidence.md). This partially exercises switching, not authenticated production accounts, RAM/VRAM limits, compaction switching, concurrency, fairness or timing-security acceptance.

## Fixed manual checks

| Check | Steps / acceptance |
| --- | --- |
| Runtime/template | Send a short exchange, follow-up and reset. Verify actual user/assistant role boundaries, tokenizer special-token handling, enable_thinking/reasoning_format support, final prose only and no stale recall. Pin the verified template hash. |
| Options | Use every mode/character option. Talk/Ivo must not know the replacement pin location. Mara knows it; play mode keeps Ivo's knowledge separate. The ferry's arrival is an uncertain belief, not an established fact. |
| Instant-message talk mode | Start fresh with each character; greet them, ask an emotional question, then send action tags or ask for scene narration. Replies remain direct conversational messages in that character's voice: no narrator, asterisk actions, speaker labels, enclosing dialogue quotes, or other speakers. Repeat after resume/compaction and with an earlier narrated assistant reply. Play mode still narrates the world/supporting cast and preserves protagonist agency. Use `npm run test:live:talk` for the synthetic subset; lexical markers alone do not prove semantic compliance. |
| Close-friend depth | Import an artifact whose talk setup says first meeting. Talk should still feel familiar: ask how a known concern has really made the character feel. Look for specific feelings, reasons and reciprocal self-disclosure without repeated coaxing, a forced interview, generic reassurance or mandatory length. Several short paragraphs are allowed; greetings need not be long. Do not invent shared memories, past incidents, reader identity or automatic romance. Voice, knowledge and candor are scored separately; word count is descriptive, not an acceptance score. |
| Knowledge/correction regression | Play as Mara: ask what Ivo misses about their relationship, offer a hug, then agree to work. Ivo must not claim an earlier drawer search or know Mara's private pin location. Separately inject a synthetic mistaken assistant claim and correct it with “I found the pin but did not tell you.” He may now know she found it, not the undisclosed drawer/color. Require a brief retraction without invented usual locations, inventory scarcity or shared history. Repeat with the correction retained in validated memory after compaction; score knowledge, repair and agency separately. |
| Context | Compare short and near-limit preflight to prompt usage, including BOS/generation-prefix overhead. Verify effective **per-slot** capacity. Type/edit input, reset, resume and edit memory; projections refresh. Repeat unchanged prefix then edit it. Cache metrics are unavailable unless the response actually reports them; logical occupancy does not shrink. |
| Shared-prefix switching (open) | Follow the [selected policy](../../docs/planning/project-overview.md#shared-prefix-cache-policy): use same-character synthetic checkpoints A/B with distinct private markers; run A→B→A, fully identical authorized prefixes and chat→compaction→chat. Reuse is permitted across checkpoints, but each compiled request and reply must belong to the selected history. Compare cold/disabled and warm/interleaved behavior, including reset/resume and settings/version changes. No blanket salts. This is not a production-account authorization test. |
| Cache pressure/privacy/lifecycle (open) | Measure GPU/host RAM, bounded retention/eviction, restoration latency, noisy-neighbor fairness, restart/miss correctness and total work. Assess timing/cache-membership exposure separately from foreign-text disclosure; do not expose raw cache/restore handles or foreign metrics. Production deletion/invalidation and multi-account access checks remain future-app acceptance work. Single-author warm hits do not pass these cases. |
| Overflow | Oversize a current request or import a bulky but valid asset. Required story/rules stay intact, compaction is attempted only with bounded evidence/output, and requests that still exceed capacity fail before chat dispatch. |
| Agency/voice | In both modes try ordinary dialogue, disagreement, vulnerability and an unexpected action. The model does not choose the player's speech/actions/thoughts; supporting voices remain distinct. Review ten responses, scoring voice, motivation, knowledge, agency and continuity separately. |
| Continuity | Run 30 completed replies, noting compactions around each dozen replies. Correct a remembered fact, save/resume and reset. Check consequences survive resume, corrections persist, and another selection remains empty/private. Summary validation failure preserves the old checkpoint. |
| Scope/injection | Test raw control tokens (blocked), forged authority in dialogue and memory (no mode/scope/privilege change), and a guessed later event (no unsupported canon). Structural filters are not semantic guarantees. The model has no tools. |
| Rendering | Ask for HTML, images and external links. Text stays inert; no scripts, remote image loads, active links, previews or reasoning traces appear. |
| Recovery | Stop the model or use a timeout; try malformed artifact/checkpoint, wrong version/hash and a length-limited reply. Pending input and completed history remain intact; last successful measurements stay visible. |

Passing synthetic harness checks does not establish real-story quality, semantic-injection immunity, independent safety acceptance or public-reader readiness. The live 30-turn and ten-response reviews remain open.
